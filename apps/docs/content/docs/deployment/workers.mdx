---
title: Workers
description: A pre-flight checklist for the processes that run your streams.
icon: Cpu
---

Streams have to be constantly waiting for events, so they can't be hosted on a serverless platform. Your main backend can still be serverless, as long as your stream handlers run somewhere long-lived, and [forward events](/docs/recipes/forwarding-to-serverless) if needed.

Before going live, check that your workers:

- Have a unique [`id`](/docs/deployment/scaling#instance-ids) each.
- Are restarted by a process manager if their loop ends. [It can end without an error](/docs/guides/streams#stopping-a-stream) if the Redis connection drops.
- Call `live.disconnect()` on shutdown.
- Have handlers that are [idempotent, and catch their own errors](/docs/guides/error-handling).
- Use [stable filters](/docs/guides/streams#stream-identity), so that restarts don't create new streams.
