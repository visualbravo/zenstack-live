The `when` option says which events you want, and each one takes the same `where` syntax as a ZenStack query, with autocomplete from your model.

```typescript
const stream = live.stream({
  model: 'Post',
  slug: 'moderate-posts',

  when: {
    created: {
      OR: [
        { title: { contains: 'ugly', mode: 'insensitive' } },
        { title: { contains: 'stupid', mode: 'insensitive' } },
      ],
    },
  },
})
```

## Choosing Event Types

The keys of `when` decide which event types you receive, and the type of `event` follows along.

| `when`                           | Receives                   | `event` type                 |
| -------------------------------- | -------------------------- | ---------------------------- |
| Omitted, or `{}`                 | Everything                 | Created, updated, or deleted |
| `{ created: {} }`                | Every new record           | Created                      |
| `{ updated: {} }`                | Every update               | Updated                      |
| `{ deleted: { role: 'ADMIN' } }` | Deleted records that match | Deleted                      |
| `{ created: {}, deleted: {} }`   | New and deleted records    | Created or deleted           |

## Watching for Transitions

`updated` takes `before` and `after`, which are matched against the record on each side of the update. Using only one of them gives you a transition, which is usually what you're after:

```typescript
when: {
  updated: {
    after: { status: 'DELIVERED' },
  },
}
```

This fires once, when an order becomes `DELIVERED`, and not every time something else about a delivered order changes.

| `updated`                 | Matches when                                          |
| ------------------------- | ----------------------------------------------------- |
| `{}`                      | Always.                                               |
| `{ after: A }`            | The record **didn't** match `A` before, and does now. |
| `{ before: A }`           | The record matched `A` before, and **doesn't** now.   |
| `{ before: A, after: B }` | The record matched `A` before, and matches `B` now.   |

Note that the last one isn't a transition. Each side is checked on its own, so `{ before: { paid: true }, after: { paid: true } }` matches any update to a paid record. To catch a specific change, describe both ends, like `{ before: { status: 'PENDING' }, after: { status: 'SHIPPED' } }`.

## Operators

Filters are validated by ZenStack, so a value is accepted here exactly when it would be accepted in a query. An invalid or unsupported filter makes `live.stream()` throw right away, instead of failing later on.

### All Scalars

These work on strings, numbers, `BigInt`, `Decimal`, `DateTime`, and custom types based on them. `Boolean` and enum fields take a subset, like `equals`, `not`, and `in` for enums. Autocomplete shows what's available for each field.

| Operator                 | Example                                 |
| ------------------------ | --------------------------------------- |
| Direct value             | `{ status: 'ACTIVE' }`                  |
| `equals`                 | `{ age: { equals: 30 } }`               |
| `not`                    | `{ age: { not: 30 } }`                  |
| `in`, `notIn`            | `{ status: { in: ['ACTIVE', 'NEW'] } }` |
| `lt`, `lte`, `gt`, `gte` | `{ age: { gte: 18 } }`                  |
| `between`                | `{ age: { between: [18, 65] } }`        |
| `null`                   | `{ deletedAt: null }`                   |

### Strings

| Operator     | Example                                                |
| ------------ | ------------------------------------------------------ |
| `contains`   | `{ title: { contains: 'live' } }`                      |
| `startsWith` | `{ title: { startsWith: 'Re:' } }`                     |
| `endsWith`   | `{ email: { endsWith: '@example.com' } }`              |
| `mode`       | `{ title: { contains: 'live', mode: 'insensitive' } }` |

`mode` applies to the filter it's in, so `not` needs its own: `{ not: { equals: 'a', mode: 'insensitive' } }`.

### Arrays

| Operator   | Example                              |
| ---------- | ------------------------------------ |
| `equals`   | `{ tags: { equals: ['a', 'b'] } }`   |
| `has`      | `{ tags: { has: 'a' } }`             |
| `hasEvery` | `{ tags: { hasEvery: ['a', 'b'] } }` |
| `hasSome`  | `{ tags: { hasSome: ['a', 'b'] } }`  |
| `isEmpty`  | `{ tags: { isEmpty: true } }`        |

### Logic

`AND`, `OR`, and `NOT` combine filters, and can be nested.

```typescript
when: {
  created: {
    role: 'ADMIN',
    NOT: { email: { endsWith: '@example.com' } },
  },
}
```

### JSON

Plain `Json` fields take a `path`, plus a condition to check at that path.

```typescript
when: {
  created: {
    metadata: { path: '$.plan', equals: 'pro' },
  },
}
```

| Filter                                                      | Checks                                   |
| ----------------------------------------------------------- | ---------------------------------------- |
| `equals`, `not`                                             | The value at `path`.                     |
| `string_contains`, `string_starts_with`, `string_ends_with` | A string at `path`. These accept `mode`. |
| `array_contains`, `array_starts_with`, `array_ends_with`    | An array at `path`.                      |

Paths support keys (`$.a.b`), quoted keys (`$."a b"`), indexes (`$.a[0]`, `$.a[last]`), and wildcards (`$.*`, `$.a[*]`). Filter expressions and `.**` aren't supported.

To tell the three kinds of null apart, use the values exported by ZenStack:

```typescript
import { AnyNull, DbNull, JsonNull } from '@zenstackhq/orm'

when: {
  created: {
    metadata: { equals: JsonNull },
  },
}
```

### Typed JSON

Fields that use a custom `type` are filtered by their own fields, and can be nested.

```typescript
when: {
  created: {
    profile: {
      name: 'Ada',
      address: { geo: { lat: { gt: 21 } } },
    },
  },
}
```

`is` and `isNot` work on objects, while `some`, `every`, and `none` work on arrays nested inside of one.

```typescript
when: {
  created: {
    profile: {
      addresses: { some: { city: 'Hanoi' } },
    },
  },
}
```

A field that's a top-level array of a custom type, like `addresses Address[] @json`, doesn't take these. It uses the [array operators](#arrays), which compare whole elements, so `{ addresses: { has: { city: 'Hanoi', tags: [] } } }` only matches an element that's exactly equal to that value.

## Null Behavior

Filters follow SQL's rules, so a comparison against `NULL` isn't true or false, it's unknown, and an unknown record doesn't match. This catches people out most often with negative filters:

```typescript
// This doesn't match records where `status` is NULL.
{
  status: {
    not: 'ARCHIVED'
  }
}

// This does.
{
  OR: [{ status: { not: 'ARCHIVED' } }, { status: null }]
}
```

The same goes for `notIn` and `NOT`.

Array fields hold a similar surprise. ZenStack reads a `NULL` array as empty, so that's what your event contains, but filters still see the `NULL`, just like a query would. `{ tags: { isEmpty: true } }` doesn't match it.

## What You Can't Filter On

Filters run in JavaScript against a single event, so anything that needs the database isn't available. Relation filters aren't part of the types, and these all throw when the stream is created:

- Relation fields
- Computed fields
- `$expr`
- `fuzzy` and `fts`
- JSON paths with filter expressions or `.**`

Two comparisons also differ slightly from Postgres. Strings are ordered by code unit and not by your database's collation, which affects `lt` and `gt`, and timestamps are compared to the millisecond.
